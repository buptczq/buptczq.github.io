LLM MoE Prefill / Decode 估算器

支持 Dense / MoE、Hybrid linear_attention + full_attention、显式 head_dim、 full_attention_layers、Top-K Expert 活跃 FLOPs 和专家权重读取估算。 内存访问为算法级估算，实际会受专家并行、权重缓存、PagedAttention、算子融合等影响。

模型参数

Hybrid 架构：KV Cache 和长序列 Attention 只按 full attention 层数 计算。

MoE 参数

MoE 推理权重读取不是固定值。 distinct 适合估算一个 batch / prefill chunk 内专家权重去重后的读取量。 per_token 更保守，假设每个 token 都重复读取专家权重。 all 按每层读取全部专家权重，接近稠密上限。

运行参数

Decode 第 1 个生成 token 的上下文长度 = Prompt 长度 + 1。

精度 / 量化

Qwen3.6 MoE config 中提供了 quantization_config: fp8， 因此预设默认将权重量化设为 FP8 / INT8 = 1 Byte。 如需 BF16 估算，请手动改回 2 Bytes。

说明

1. MoE FLOPs 按 Top-K routed experts + shared expert 计算：
top_k × expert_ffn + shared_expert_ffn + router。

2. MoE 权重读取支持三种模式。默认 distinct：一个 prefill chunk 或一个 decode step 内， 每层最多读取 min(num_experts, tokens × top_k) 个 routed expert。

3. Qwen3.6 / Qwen3.5 MoE 是 Hybrid 架构：linear_attention + full_attention。 本计算器只把 full attention 层计入增长型 KV Cache 和二次注意力 FLOPs；linear attention 的固定状态、 卷积、特殊投影未精确建模。

4. Vision Tower、MTP、attn_output_gate、router auxiliary loss 等未计入。 这里估算的是 text decoder 主体的近似值。
